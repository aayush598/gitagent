\subsection*{Executive Summary}
The codebase does not explicitly handle IPv6 connectivity. In \srcfile{src/voice/server.ts:1942}, URL parsing creates URLs with \code{http://localhost:\$\{port\}} which resolves only to IPv4 \code{127.0.0.1}, not IPv6 \code{::1}. In IPv6-only environments (certain cloud containers, Tailscale, some Kubernetes clusters), the voice server binds to IPv6 but clients connecting via \code{localhost} will fail. Additionally, no DNS resolution preference is configured, causing dual-stack timeout issues on systems with broken IPv6 connectivity.

\subsection*{Root Cause Analysis}
Hardcoded \code{localhost} and no DNS ordering:

\begin{lstlisting}[language=TypeScript]
// BEFORE — http://localhost resolves only to IPv4
const url = new URL(req.url || "/", `http://localhost:${port}`);

// No DNS preference set
// Default behavior may try IPv6 first, causing 5-10s timeout
\end{lstlisting}

\subsection*{Fix Implementation}
DNS ordering is configured and \code{localhost} is replaced with explicit IP:

\begin{lstlisting}[language=TypeScript]
// AFTER — DNS order and explicit IP
import { setDefaultResultOrder } from "dns";

// At the top of src/index.ts
setDefaultResultOrder("ipv4first");

// In src/voice/server.ts — use 127.0.0.1 explicitly
const url = new URL(req.url || "/", `http://127.0.0.1:${port}`);
\end{lstlisting}

\subsection*{Affected Files}
\begin{itemize}

    \item \srcfile{src/voice/server.ts} — URL construction with 127.0.0.1
