\subsection*{Executive Summary}
The agent tool execution pipeline had no rate limiting whatsoever. The LLM could call any tool---\texttt{cli}, \texttt{read}, \texttt{write}, \texttt{memory}, \texttt{edit}---as many times as it wanted with no cooldown, no per-session quota, and no concurrency limit. This transforms any single-vulnerability exploit into a denial-of-service attack vector. The fix introduces a sliding-window rate limiter with per-tool call quotas, integrated into the SDK's tool-wrapping pipeline.

\subsection*{Root Cause Analysis}
Each tool's \texttt{execute()} function was called directly with no throttling. The CLI tool spawned a new shell process per call. With rapid calls, the system could experience process table exhaustion, memory exhaustion, file descriptor exhaustion, and disk space exhaustion. No semaphore, mutex, or per-session quota existed.

\subsection*{Fix Implementation}
The fix introduces a \texttt{RateLimiter} class in \srcfile{src/tools/rate-limiter.ts} implementing a sliding-window algorithm with configurable per-tool defaults:

\begin{lstlisting}[language=TypeScript]
const DEFAULT_LIMITS: Record<string, RateLimitConfig> = {
    cli: { maxCalls: 10, windowMs: 60000 },
    write: { maxCalls: 30, windowMs: 60000 },
    read: { maxCalls: 60, windowMs: 60000 },
    edit: { maxCalls: 30, windowMs: 60000 },
    memory: { maxCalls: 20, windowMs: 60000 },
    task_tracker: { maxCalls: 30, windowMs: 60000 },
    skill_learner: { maxCalls: 10, windowMs: 60000 },
    capture_photo: { maxCalls: 10, windowMs: 60000 },
};
\end{lstlisting}

The \texttt{wrapToolWithRateLimit()} function wraps each tool, calling \texttt{rateLimiter.check(tool.name)} before every execution. It is applied in \texttt{src/sdk.ts} before OpenTelemetry instrumentation, ensuring the rate limit check runs outermost.

\subsection*{Verification}
8 tests verify: calls under the limit succeed, calls over the limit throw, retry-after info in error messages, independent tool limits, unconfigured tools pass through, per-tool \texttt{reset()}, global \texttt{reset()}, and all 8 configured tool types enforce their specific limits independently.
