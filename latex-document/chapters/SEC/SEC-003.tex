\subsection*{Executive Summary}
When GitAgent starts, it reads the \texttt{.env} file from the agent directory and injects every key-value pair directly into \texttt{process.env} (\srcfile{src/index.ts:379-391}). This global namespace is then inherited by all child processes spawned by the \texttt{cli} tool via \texttt{env: \{ ...process.env \}}. The consequence is that any shell command the LLM executes---including commands that contain injection payloads---has unfettered access to every API key, token, and secret the agent uses: \texttt{OPENAI\_API\_KEY}, \texttt{ANTHROPIC\_API\_KEY}, \texttt{GITHUB\_TOKEN}, and any custom variables the user placed in \texttt{.env}.

The root cause is twofold: \texttt{.env} variables are loaded into the shared global \texttt{process.env} instead of a scoped configuration object, and child processes spawned by the CLI tool, declarative tool system, and hook scripts blindly forward \texttt{process.env} instead of constructing a minimal filtered environment. The fix introduces a shared \texttt{createSafeEnv()} utility in \srcfile{src/tools/shared.ts} that constructs an allowlist of safe system variables, and applies it to all three spawn locations.

\subsection*{Root Cause Analysis}
The environment forwarding pattern existed in three critical locations, of which only two were initially patched. The CLI tool (\srcfile{src/tools/cli.ts}), the most dangerous attack vector since the LLM directly controls its command string, was left unfixed:

\begin{lstlisting}[language=TypeScript]
// cli.ts — the PRIMARY attack vector (LLM-controlled commands)
const child = spawn("sh", ["-c", command], {
    cwd,
    stdio: ["ignore", "pipe", "pipe"],
    env: { ...process.env },  // ALL env vars forwarded
});
\end{lstlisting}

The same pattern appeared in \srcfile{src/hooks.ts} and \srcfile{src/tool-loader.ts}, both previously patched with inline duplicate code. The fix consolidates all three into a single shared utility.

\subsection*{Fix Implementation}
A shared \texttt{createSafeEnv()} function was extracted into \srcfile{src/tools/shared.ts} to eliminate code duplication and ensure consistent behavior across all spawn locations:

\begin{lstlisting}[language=TypeScript]
const SAFE_ENV_KEYS = [
    "PATH", "HOME", "USER", "SHELL", "TERM",
    "LANG", "LC_ALL", "PWD", "TMPDIR", "TEMP", "TMP",
];

export function createSafeEnv(): Record<string, string | undefined> {
    const env: Record<string, string | undefined> = {};
    for (const key of SAFE_ENV_KEYS) {
        if (process.env[key] !== undefined) env[key] = process.env[key];
    }
    return env;
}
\end{lstlisting}

This function returns a fresh object each call, preventing mutation of the shared environment, and only copies the explicitly allowlisted system variables. Each spawn location is updated to a single-line call:

\begin{lstlisting}[language=TypeScript]
// cli.ts — the primary attack vector, now protected
const child = spawn("sh", ["-c", command], {
    cwd,
    stdio: ["ignore", "pipe", "pipe"],
    env: createSafeEnv(),
});
\end{lstlisting}

The same pattern replaces the inline duplicate code in \srcfile{src/hooks.ts} and \srcfile{src/tool-loader.ts}. By consolidating into a shared function, future spawn additions automatically get the same protection.

\subsection*{Affected Files}
\begin{itemize}
    \item \srcfile{src/tools/shared.ts} --- Added \texttt{createSafeEnv()} utility function with allowlist of 11 safe system variables.
    \item \srcfile{src/tools/cli.ts} --- Replaced \texttt{env: \{ ...process.env \}} with \texttt{env: createSafeEnv()} in the CLI spawn call. This was the primary attack vector and was missing from the initial fix.
    \item \srcfile{src/hooks.ts} --- Replaced inline \texttt{safeEnv} construction with shared \texttt{createSafeEnv()} import.
    \item \srcfile{src/tool-loader.ts} --- Replaced inline \texttt{safeEnv} construction with shared \texttt{createSafeEnv()} import.
\end{itemize}

\subsection*{Verification}
Verification is performed by unit tests in \srcfile{test/env.test.ts} that confirm \texttt{createSafeEnv()} includes essential system variables (PATH, HOME) while excluding arbitrary test secret variables. The tests also verify the function returns a new object on each call (no shared mutable state) and does not return a reference to \texttt{process.env}.

\subsection*{Test File}
\srcfile{test/env.test.ts}

Four unit tests covering: inclusion of essential vars, exclusion of unknown vars, immutability (new object per call), and isolation (returned object does not reference \texttt{process.env}).
