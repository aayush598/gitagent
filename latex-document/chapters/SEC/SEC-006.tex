\subsection*{Executive Summary}
The \texttt{write} tool writes content to user-specified file paths without verifying whether the path resolves to a symlink. An attacker who can control the file path argument---either directly via loaded agent prompts or indirectly via prompt injection---can instruct the agent to write to a symlink that points to an arbitrary location on the filesystem. The attack works by first creating a symlink in the agent's writable directory that points to a sensitive target (e.g., \texttt{$\sim$/.ssh/authorized\_keys}), then asking the agent to write to that symlink path. The \texttt{writeFile} call follows the symlink and writes the attacker's content to the target.

The fix provides defense in depth: (1) \texttt{assertNotSymlink()} uses \texttt{lstat} to detect symlinks at the final path component before any file operation, (2) \texttt{resolveSafePath()} resolves all symlinks in the path via \texttt{realpathSync} and verifies the real target is within the workspace, and (3) TOCTOU-safe I/O wrappers (\texttt{safeReadFile}/\texttt{safeWriteFile}) open the file first and validate through the open file descriptor.

\subsection*{Root Cause Analysis}
The vulnerable code path in \srcfile{src/tools/write.ts}:

\begin{lstlisting}[language=TypeScript]
const absolutePath = resolvePath(path, cwd);
await writeFile(absolutePath, content, "utf-8");
\end{lstlisting}

\texttt{writeFile()} in Node.js follows symlinks by default. If \texttt{absolutePath} is a symlink, the write targets the symlink's destination. There is no \texttt{lstat} call to check for symlinks before the write. The same pattern exists in \texttt{edit.ts}. Additionally, the \texttt{resolvePath} function does not follow or validate symlinks in path components (e.g., a subdirectory that is a symlink to another location).

\subsection*{Fix Implementation}
The fix introduces three layers of defence:

\paragraph{Layer 1: \texttt{assertNotSymlink()}} An early-exit check using \texttt{lstat} that detects if the final path component is a symbolic link:

\begin{lstlisting}[language=TypeScript]
export async function assertNotSymlink(path: string): Promise<void> {
    try {
        const stats = await lstat(path);
        if (stats.isSymbolicLink()) {
            throw new Error(`Path is a symbolic link -- blocked for security`);
        }
    } catch (err: any) {
        if (err.message?.includes("symbolic link")) throw err;
    }
}
\end{lstlisting}

\paragraph{Layer 2: \texttt{resolveSafePath()}} A path resolution function that uses \texttt{realpathSync} to follow all symlinks in the path and verifies the ultimate target is within the allowed base directory:

\begin{lstlisting}[language=TypeScript]
export function resolveSafePath(path: string, cwd: string): string {
    // ... validation and symlink resolution ...
    const realResolved = realpathSync(resolved);
    if (relative(allowedBase, realResolved).startsWith(".."))
        throw new Error("Path traversal detected (symlink resolved)");
    return resolved;
}
\end{lstlisting}

\paragraph{Layer 3: \texttt{safeReadFile}/\texttt{safeWriteFile()}} TOCTOU-safe I/O that opens the file first, resolves the real path through the open file descriptor, and validates it before reading or writing.

\paragraph{Integration:} In \texttt{write.ts}, both \texttt{assertNotSymlink} and \texttt{safeWriteFile} are used:

\begin{lstlisting}[language=TypeScript]
// validate directory not a symlink before mkdir
await assertNotSymlink(resolvedDir);
// validate final path not a symlink before write
await assertNotSymlink(resolveSafePath(path, cwd));
// fd-based TOCTOU-safe write
await safeWriteFile(path, content, cwd);
\end{lstlisting}

The same pattern is applied in \texttt{edit.ts} and \texttt{read.ts}.

\subsection*{Verification}
The test suite in \texttt{test/symlink-attack.test.ts} covers 18 test cases across four suites:

\textbf{resolveSafePath (7 tests)}: Validates rejection of absolute paths, home directory expansion, \texttt{../} traversal, and null byte injection; validates resolution of relative and subdirectory paths.

\textbf{assertNotSymlink (5 tests)}: Validates that file symlinks are detected, directory symlinks are detected, and regular files, directories, and non-existent paths are allowed.

\textbf{Symlink protection (3 tests)}: Validates that symlinks pointing outside the workspace are caught, symlinks within the workspace are allowed, and non-existent file paths are handled correctly.

\textbf{Defense-in-depth (3 tests)}: Validates that both \texttt{resolveSafePath} and \texttt{assertNotSymlink} work together, catching both the path-level and component-level symlink attacks.
