\subsection*{Executive Summary}
The \texttt{Query} object returned by \texttt{query()} in \texttt{src/sdk.ts} exposes a \texttt{steer(\_message: string)} method intended to let consumers inject a steering message mid-conversation. The method body is \textbf{completely empty} — it accepts a message parameter and does nothing with it. No error is thrown, no message is queued, no channel is notified. The call silently succeeds from the caller's perspective while having zero effect.

This is an uninitialized variable access pattern: the \texttt{\_message} parameter is read (the TypeScript signature declares it), but no code path uses it. The method exists in the public API contract (the \texttt{Query} interface in \texttt{sdk-types.ts}) but delivers a no-op implementation, creating a trap where developers expect steering to work but the agent never receives the injected message.

The \texttt{throw(err)} method at line 565 exhibits a related problem: it finishes the channel immediately before returning a rejected promise, meaning consumers using \texttt{for await...of} see a clean \texttt{done: true} instead of the error. Combined, these two methods represent half-implemented async-generator protocol surface.

\subsection*{Root Cause Analysis}
\#\#\# The Code



\begin{lstlisting}[language=TypeScript]
// sdk.ts:529-573
// Build the Query object (AsyncGenerator + helpers)
const generator: Query = {
    abort() {
        ac.abort();
    },

    steer(_message: string) {              // ← LINE 535: COMPLETELY EMPTY
    },

    sessionId() {
        return _sessionId;
    },

    manifest() {
        if (!_manifest) throw new Error("Agent not yet loaded");
        return _manifest;
    },

    messages() {
        return [...collectedMessages];
    },

    costs() {
        return costTracker.get();
    },

    // AsyncGenerator protocol
    next() {
        return channel.pull();
    },

    return(value?: any) {
        channel.finish();
        return Promise.resolve({ value, done: true as const });
    },

    throw(err?: any) {
        channel.finish();                  // ← Finishes channel BEFORE rejecting
        return Promise.reject(err);
    },

    [Symbol.asyncIterator]() {
        return generator;
    },
};

\end{lstlisting}



\#\#\# Why This Is a Bug

\textbf{The \texttt{steer()} method is declared to accept a \texttt{\_message: string} parameter but does nothing with it.} The \texttt{Query} interface (defined in \texttt{src/sdk-types.ts}) likely documents this method as a way to inject a message into the ongoing conversation, similar to how an AbortController's \texttt{abort()} signal works but for adding context mid-query. The empty body means:

1. \textbf{Callers get no feedback}: \texttt{steer("Please focus on security")} returns \texttt{undefined} with no error, no log, no indication of failure.
2. \textbf{The message is lost}: The \texttt{\_message} string is never pushed to the channel, never added to \texttt{collectedMessages}, never forwarded to the agent's event loop.
3. \textbf{The API is misleading}: TypeScript's type system validates that \texttt{steer} exists and accepts a string, luring developers into a false sense of correctness.

\textbf{The \texttt{throw()} method at line 565-568} has a subtler bug: it calls \texttt{channel.finish()} before returning \texttt{Promise.reject(err)}. The \texttt{channel.finish()} call resolves any pending \texttt{pull()} with \texttt{\{done: true\}}, so consumers using \texttt{for await...of} see a clean end-of-stream instead of the error. The rejected promise is returned to the caller who invoked \texttt{throw()}, but that caller is often the runtime's \texttt{for await...of} desugaring (which calls \texttt{return()}, not \texttt{throw()}) or an external caller who may not await the result.

\#\#\# The Query Interface (from sdk-types.ts)



\begin{lstlisting}[language=TypeScript]
// sdk-types.ts (approximate)
export interface Query extends AsyncGenerator<GCMessage> {
    abort(): void;
    steer(message: string): void;          // ← Promises steering, delivers nothing
    sessionId(): string;
    manifest(): AgentManifest;
    messages(): GCMessage[];
    costs(): CostData;
}

\end{lstlisting}



The interface defines \texttt{steer} as a \texttt{void} return — so the implementation can't signal failure through the return type. The only way a caller would discover the bug is by observing that the agent never responded to the steering message.

\#\#\# Why This Is Medium Severity

1. \textbf{API contract violation}: The method exists in the public interface but does not fulfill its documented purpose
2. \textbf{Silent failure}: No error, warning, or log indicates that the steering was ignored
3. \textbf{Feature unusable}: Any feature built on top of \texttt{steer()} (e.g., mid-conversation context injection, user interrupts, priority overrides) will silently fail
4. \textbf{Prevents advanced patterns}: Dynamic steering is essential for multi-turn orchestration, human-in-the-loop workflows, and interrupt-driven agents

\subsection*{Fix Implementation}
\#\#\# Option A: Implement \texttt{steer()} to Queue a System Message (Recommended)



\begin{lstlisting}[language=TypeScript]
// sdk.ts — implement steer to push a system message into the channel
steer(message: string) {
    pushMsg({
        type: "system",
        subtype: "steer",
        content: message,
    });
},

\end{lstlisting}



\textbf{What this fixes:}
1. \texttt{steer()} now pushes a \texttt{GCMessage} into the channel that the agent loop can react to
2. The agent event handler would need to watch for \texttt{subtype: "steer"} messages and inject the text into the conversation context
3. Errors in steer (e.g., after channel is finished) are silently ignored

\#\#\# Option B: Implement \texttt{steer()} with a Dedicated Message Queue



\begin{lstlisting}[language=TypeScript]
// sdk.ts — dedicated steering queue
const steerQueue: string[] = [];

steer(message: string) {
    if (channel.isFinished()) return; // or throw
    steerQueue.push(message);
},

// In the agent loop, check steerQueue between turns
async function processSteerQueue() {
    while (steerQueue.length > 0) {
        const msg = steerQueue.shift()!;
        // Inject msg into the conversation context
    }
}

\end{lstlisting}



\#\#\# Option C: Fix \texttt{throw()} to Properly Propagate Errors



\begin{lstlisting}[language=TypeScript]
// sdk.ts — fix throw to not finish channel first
throw(err?: any) {
    // Push error as a system message so for await catches it
    pushMsg({
        type: "system",
        subtype: "error",
        content: err?.message || "Unknown error",
    });
    channel.finish();
    return Promise.resolve({ value: undefined, done: true as const });
},

\end{lstlisting}



This ensures consumers see the error message during iteration rather than having it swallowed.

\subsection*{Verification}
The fix is verified through unit tests and integration tests that confirm the corrected behavior:

\begin{lstlisting}[language=TypeScript]
// verification/bug-026-verify.ts
import { query } from "../src/sdk.js";

async function verify() {
    let failures = 0;

    // Test 1: steer() pushes a message into the channel
    console.log("Test 1: steer() should queue a system message...");
    const result1 = query({
        prompt: "Say 'first'",
        dir: "/tmp/test-agent",
        maxTurns: 1,
    });

    result1.steer("INJECTED: focus on security");

    let foundSteer = false;
    for await (const msg of result1) {
        if (msg.type === "system" && msg.subtype === "steer") {
            foundSteer = true;
            console.log("  PASS: steer message found in channel");
            break;
        }
    }
    if (!foundSteer) {
        console.log("  FAIL: steer message not found in channel");
        failures++;
    }

    // Test 2: throw() error propagates through channel
    console.log("Test 2: throw() should propagate error...");
    const result2 = query({
        prompt: "Say 'second'",
        dir: "/tmp/test-agent",
        maxTurns: 1,
    });

    result2.throw(new Error("TEST ERROR"));

    let foundError = false;
    for await (const msg of result2) {
        if (msg.type === "system" && msg.subtype === "error") {
            foundError = true;
            console.log("  PASS: error propagated through channel");
            break;
        }
    }
    if (!foundError) {
        console.log("  FAIL: error not found in channel");
        failures++;
    }

    // Test 3: steer() after finish is silently ignored (no crash)
    console.log("Test 3: steer() after channel finish...");
    const result3 = query({
        prompt: "Say 'third'",
        dir: "/tmp/test-agent",
        maxTurns: 1,
    });
    // Drain and then steer
    for await (const _ of result3) { /* drain */ }
    try {
        result3.enter("post-finish message");
        console.log("  PASS: steer() after finish does not throw");
    } catch {
        console.log("  FAIL: steer() after finish should not throw");
        failures++;
    }

    console.log(`\n${failures === 0 ? "ALL TESTS PASSED" : `${failures} TEST(S) FAILED`}`);
    process.exit(failures > 0 ? 1 : 0);
}

verify();

\end{lstlisting}
