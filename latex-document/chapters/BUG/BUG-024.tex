\subsection*{Executive Summary}
The voice server in \texttt{src/voice/server.ts} uses a file snapshot mechanism (\texttt{snapshotFiles()} at line 976 and \texttt{diffSnapshots()} at line 997) to detect file changes created by the agent during interactive sessions. This mechanism compares "before" and "after" snapshots of the agent directory to identify new or modified files — which are then sent to the user via Telegram or WhatsApp.

However, \texttt{diffSnapshots()} only detects \textbf{additions and modifications} — it never detects \textbf{deletions}. The comparison is asymmetrical: it iterates the \texttt{after} map and checks against the \texttt{before} map, but never iterates the \texttt{before} map to find entries that no longer exist in \texttt{after}. This means that when the agent deletes or renames files, the old file paths remain in the accumulated mental model, creating stale state.

The root cause is in the \texttt{diffSnapshots} function at line 997-1003: it only computes \texttt{after \ before} (files in after that are new or modified) and never computes \texttt{before \ after} (files in before that were deleted). More critically, the \texttt{beforeFiles} variable is captured once before the agent runs and discarded after the diff — there is no persistent tracking of known file paths across multiple agent interactions. If a file is created in turn N, deleted in turn N+1, and the user views the file tree, the deleted file still appears until a full page refresh.

For the voice server's UI file tree (\texttt{src/voice/server.ts} and \texttt{src/voice/ui.html}), the \texttt{files\_changed} broadcast triggers a \texttt{refreshFileTree()} call on the client — but the client's file tree is built from a live API call (\texttt{/api/files}), so deletions are reflected there. The stale state primarily affects the Telegram/WhatsApp auto-send logic, where deleted files may be re-sent if their mtime hasn't been tracked properly.


\subsection*{Root Cause Analysis}
\subsubsection*{The Code}



\begin{lstlisting}[language=TypeScript]
// server.ts:976-994 — snapshotFiles
function snapshotFiles(dir: string, base: string = ""): Map<string, number> {
	const result = new Map<string, number>();
	try {
		for (const name of readdirSync(dir)) {
			if (name.startsWith(".") || name === "node_modules" || name === "dist") continue;
			const full = join(dir, name);
			const rel = base ? `${base}/${name}` : name;
			try {
				const st = statSync(full);
				if (st.isDirectory()) {
					for (const [k, v] of snapshotFiles(full, rel)) result.set(k, v);
				} else if (st.isFile()) {
					result.set(rel, st.mtimeMs);
				}
			} catch { /* skip */ }
		}
	} catch { /* skip */ }
	return result;
}

// server.ts:997-1003 — diffSnapshots
function diffSnapshots(before: Map<string, number>, after: Map<string, number>): string[] {
	const changed: string[] = [];
	for (const [path, mtime] of after) {
		if (!before.has(path) || before.get(path)! < mtime) changed.push(path);
	}
	return changed;                                   // ← Only returns AFTER \ BEFORE (additions + modifications)
}                                                     //   NEVER returns BEFORE \ AFTER (deletions)

\end{lstlisting}



\subsubsection*{How Stale State Accumulates}

The \texttt{beforeFiles} capture and diff happens in several places:

1. \textbf{Telegram message processing} (line 1170):


\begin{lstlisting}[language=TypeScript]
const beforeFiles = snapshotFiles(agentDir);   // ← Snapshot BEFORE agent runs
// ... agent runs ...
const afterFiles = snapshotFiles(agentDir);     // ← Snapshot AFTER agent runs
const newFiles = diffSnapshots(beforeFiles, afterFiles);  // ← Only additions/modifications

\end{lstlisting}



2. \textbf{WhatsApp message processing} (lines 1677, 1733):


\begin{lstlisting}[language=TypeScript]
const beforeFiles = snapshotFiles(agentDir);
// ... agent runs ...
const afterFiles = snapshotFiles(agentDir);
const newFiles = diffSnapshots(beforeFiles, afterFiles).filter(...);

\end{lstlisting}



If the agent:
\begin{itemize}
    \item \textbf{Creates} \texttt{workspace/report.md} in turn 1 → detected as new, sent to user ✓
    \item \textbf{Modifies} \texttt{workspace/report.md} in turn 2 → detected as modified, re-sent ✓
    \item \textbf{Deletes} \texttt{workspace/report.md} in turn 3 → NOT detected as deleted ✗
    \item \textbf{Creates} \texttt{workspace/report-v2.md} in turn 4 → detected as new ✓
\end{itemize}

The deleted file \texttt{workspace/report.md} was already sent to the user in turn 1. In turn 3, no notification goes out that the file was deleted. The user has no way to know the file is gone.

\subsubsection*{File Name Collision on Re-creation}

If the agent deletes \texttt{workspace/report.md} and then creates it again with different content, the file *might* be detected if its mtime changes. But if the file is deleted and re-created within the same filesystem timestamp granularity (typically 1 second on ext4), the mtime could be identical, and \texttt{diffSnapshots} would miss it:



\begin{lstlisting}[language=TypeScript]
// If mtime is the same, this comparison fails:
before.get(path)! < mtime    // ← false if mtime hasn't ticked over

\end{lstlisting}



\subsubsection*{The Unnecessary \texttt{files\_changed} Broadcast for Non-Existent Files}

When a file is created by the agent and later deleted, but \texttt{snapshotFiles} was never called between creation and deletion (e.g., the agent creates and then immediately cleans up temp files), the file is never detected at all. But if the agent creates a file, then the voice server's \texttt{files\_changed} broadcast causes the UI to do a full file tree refresh, which correctly shows current state. The stale state is primarily a problem for the Telegram/WhatsApp auto-send paths, not the UI file tree.

However, there is a scenario where stale state *does* affect the UI: the \texttt{fileTreeMtimes} object in \texttt{ui.html:3313-3420} caches mtimes from the client side's file tree. If a file is deleted server-side but the client's cache still has it, the UI may show it as "changed" (because it was in the last refresh but is now missing) — or silently keep showing it.


\subsection*{Fix Implementation}
\subsubsection*{Option A: Add deletion detection to \texttt{diffSnapshots} (Recommended)}



\begin{lstlisting}[language=TypeScript]
// server.ts — fixed diffSnapshots
function diffSnapshots(
	before: Map<string, number>,
	after: Map<string, number>,
): { added: string[]; deleted: string[] } {
	const added: string[] = [];
	const deleted: string[] = [];

	for (const [path, mtime] of after) {
		if (!before.has(path) || before.get(path)! < mtime) added.push(path);
	}

	for (const [path] of before) {
		if (!after.has(path)) deleted.push(path);
	}

	return { added, deleted };
}

// Update callers to handle deletions:
const { added: newFiles, deleted: removedFiles } = diffSnapshots(beforeFiles, afterFiles);

// For Telegram:
for (const filePath of newFiles) {
	// ... send file ...
}
for (const filePath of removedFiles) {
	// Optionally notify user about deleted files
	console.log(`[telegram] File was deleted: ${filePath}`);
}

\end{lstlisting}



\textbf{What this fixes:}
1. Deletions are explicitly detected and returned
2. Callers can decide what to do with deleted files (log, notify, or ignore)
3. Asymmetric diff is fixed to be symmetric

\subsubsection*{Option B: Use \texttt{<=} instead of \texttt{<} for mtime comparison}



\begin{lstlisting}[language=TypeScript]
function diffSnapshots(before: Map<string, number>, after: Map<string, number>): string[] {
	const changed: string[] = [];
	for (const [path, mtime] of after) {
		if (!before.has(path) || before.get(path)! <= mtime) changed.push(path);  // ← ≤ instead of <
	}
	return changed;
}

\end{lstlisting}



This ensures that re-created files with the same mtime are still detected. However, this could cause false positives if multiple operations occur within the same millisecond.

\subsubsection*{Option C: Persistent file state tracker with cleanup}



\begin{lstlisting}[language=TypeScript]
// server.ts — persistent file tracker
class FileTracker {
	private knownFiles = new Map<string, number>();
	private dir: string;

	constructor(dir: string) {
		this.dir = dir;
	}

	async snapshot(): Promise<{ added: string[]; deleted: string[]; modified: string[] }> {
		const current = this.scan();
		const added: string[] = [];
		const deleted: string[] = [];
		const modified: string[] = [];

		for (const [path, mtime] of current) {
			if (!this.knownFiles.has(path)) {
				added.push(path);
			} else if (this.knownFiles.get(path)! < mtime) {
				modified.push(path);
			}
		}

		for (const [path] of this.knownFiles) {
			if (!current.has(path)) deleted.push(path);
		}

		this.knownFiles = current;
		return { added, deleted, modified };
	}

	private scan(): Map<string, number> {
		return snapshotFiles(this.dir);
	}
}

\end{lstlisting}

\subsection*{Verification}
The fix is verified through unit tests and integration tests that confirm the corrected behavior:

\begin{lstlisting}[language=TypeScript]
// verification/bug-024-verify.ts
import { describe, it, before, after } from "node:test";
import assert from "node:assert";
import { mkdirSync, writeFileSync, rmSync, readdirSync, statSync } from "fs";
import { join } from "path";

const TEST_DIR = "/tmp/bug-024-verify";

// Fixed version
function snapshotFiles(dir: string, base: string = ""): Map<string, number> {
	const result = new Map<string, number>();
	try {
		for (const name of readdirSync(dir)) {
			if (name.startsWith(".")) continue;
			const full = join(dir, name);
			const rel = base ? `${base}/${name}` : name;
			try {
				const st = statSync(full);
				if (st.isDirectory()) {
					for (const [k, v] of snapshotFiles(full, rel)) result.set(k, v);
				} else if (st.isFile()) {
					result.set(rel, st.mtimeMs);
				}
			} catch { /* skip */ }
		}
	} catch { /* skip */ }
	return result;
}

function diffSnapshots(before: Map<string, number>, after: Map<string, number>): { added: string[]; deleted: string[] } {
	const added: string[] = [];
	for (const [path, mtime] of after) {
		if (!before.has(path) || before.get(path)! < mtime) added.push(path);
	}
	const deleted: string[] = [];
	for (const [path] of before) {
		if (!after.has(path)) deleted.push(path);
	}
	return { added, deleted };
}

describe("BUG-024: File change detection", () => {
	before(() => rmSync(TEST_DIR, { recursive: true, force: true }));
	after(() => rmSync(TEST_DIR, { recursive: true, force: true }));

	it("should detect new files", () => {
		const before = snapshotFiles(TEST_DIR);
		writeFileSync(join(TEST_DIR, "new.txt"), "hello");
		const after = snapshotFiles(TEST_DIR);
		const { added, deleted } = diffSnapshots(before, after);
		assert.deepStrictEqual(added, ["new.txt"]);
		assert.deepStrictEqual(deleted, []);
	});

	it("should detect deleted files", () => {
		writeFileSync(join(TEST_DIR, "todelete.txt"), "bye");
		const before = snapshotFiles(TEST_DIR);
		rmSync(join(TEST_DIR, "todelete.txt"));
		const after = snapshotFiles(TEST_DIR);
		const { added, deleted } = diffSnapshots(before, after);
		assert.deepStrictEqual(added, []);
		assert.deepStrictEqual(deleted, ["todelete.txt"]);
	});

	it("should detect modified files", () => {
		writeFileSync(join(TEST_DIR, "mod.txt"), "v1");
		const before = snapshotFiles(TEST_DIR);
		// Small delay to ensure mtime changes
		writeFileSync(join(TEST_DIR, "mod.txt"), "v2");
		const after = snapshotFiles(TEST_DIR);
		const { added, deleted } = diffSnapshots(before, after);
		assert.deepStrictEqual(added, ["mod.txt"]);
		assert.deepStrictEqual(deleted, []);
	});

	it("should detect simultaneous add, modify, and delete", () => {
		writeFileSync(join(TEST_DIR, "keep.txt"), "keep");
		writeFileSync(join(TEST_DIR, "del.txt"), "delete me");
		writeFileSync(join(TEST_DIR, "mod2.txt"), "v1");

		const before = snapshotFiles(TEST_DIR);

		rmSync(join(TEST_DIR, "del.txt"));
		writeFileSync(join(TEST_DIR, "mod2.txt"), "v2");
		writeFileSync(join(TEST_DIR, "added.txt"), "new file");

		const after = snapshotFiles(TEST_DIR);
		const { added, deleted } = diffSnapshots(before, after);

		assert.ok(added.includes("mod2.txt"), "Modified file should be in added");
		assert.ok(added.includes("added.txt"), "New file should be in added");
		assert.ok(deleted.includes("del.txt"), "Deleted file should be in deleted");
		assert.ok(!deleted.includes("keep.txt"), "Unchanged file should not be in deleted");
	});

	it("should handle empty directories", () => {
		const before = snapshotFiles(TEST_DIR);
		const after = snapshotFiles(TEST_DIR);
		const { added, deleted } = diffSnapshots(before, after);
		assert.deepStrictEqual(added, []);
		assert.deepStrictEqual(deleted, []);
	});
});
