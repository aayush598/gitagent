\subsection*{Executive Summary}
The \texttt{createEditTool} function in \texttt{src/tools/edit.ts:56-58} conditionally appends the \texttt{g} (global) flag to the regex flags string when \texttt{replace\_all} is \texttt{true}. However, the same function on line 65 creates a second regex instance for counting matches that also independently appends the \texttt{g} flag. While JavaScript's \texttt{RegExp} constructor silently ignores duplicate flags (e.g., \texttt{"gg"} is treated as \texttt{"g"}), the fact that the same module has two different approaches to ensuring the \texttt{g} flag is present — one that checks for duplicates and one that doesn't — is a code quality issue.

More critically, the discrepancy between the flags used for the match-counting regex (line 65, which always adds \texttt{g} if absent) and the replacement regex (line 61, which only adds \texttt{g} if \texttt{replace\_all} is true) means that the match-counting regex may report a different number of matches than the replacement regex will actually replace. If the user passes a regex without \texttt{g} and \texttt{replace\_all} is \texttt{false}, the match-counting regex adds \texttt{g} internally (to count all matches for the "more than 1" check), but the replacement regex only replaces the first match. This asymmetry is confusing and potentially error-prone.

The core issue is the lack of a centralized, single code path for constructing the regex flags, leading to two different flag-building strategies in the same function.


\subsection*{Root Cause Analysis}
\subsubsection*{The Code}



\begin{lstlisting}[language=TypeScript]
// edit.ts:56-65
if (regex) {
    let rxFlags = flags || "";
    if (replace_all && !rxFlags.includes("g")) rxFlags += "g";      // Line 58: Conditionally adds 'g'

        new RegExp(old_string, rxFlags.includes("g") ? rxFlags : rxFlags + "g")  // Line 65: Independently ensures 'g'
    );
    replacements = matches ? matches.length : 0;
    // ...
    updated = original.replace(rx, new_string);                      // Line 75: Uses rx (from line 61)
}

\end{lstlisting}



\subsubsection*{The Two Flag-Building Paths}

\textbf{Path A: Replacement regex (line 58 + line 61)}



\begin{lstlisting}[language=TypeScript]
let rxFlags = flags || "";
if (replace_all && !rxFlags.includes("g")) rxFlags += "g";
const rx = new RegExp(old_string, rxFlags);

\end{lstlisting}



This builds \texttt{rxFlags} with the \texttt{g} flag added only if:
\begin{itemize}
    \item \texttt{replace\_all} is \texttt{true}
    \item \texttt{g} is not already in the flags
\end{itemize}

\textbf{Path B: Match-counting regex (line 65)}



\begin{lstlisting}[language=TypeScript]
const matchFlags = rxFlags.includes("g") ? rxFlags : rxFlags + "g";
const matches = original.match(new RegExp(old_string, matchFlags));

\end{lstlisting}



This builds \texttt{matchFlags} by adding \texttt{g} if it's NOT already present in \texttt{rxFlags}, regardless of \texttt{replace\_all}.

\subsubsection*{The Asymmetry}

| Scenario | \texttt{rxFlags} (line 57-58) | Replacement \texttt{rx} (line 61) | Match regex (line 65) | Match count vs Replace count |
|---|---|---|---|---|
| \texttt{replace\_all=false}, no flags | \texttt{""} | \texttt{/pattern/} (replaces 1) | \texttt{/pattern/g} (counts all) | Match count may be >1 but only 1 replaced |
| \texttt{replace\_all=true}, no flags | \texttt{"g"} | \texttt{/pattern/g} (replaces all) | \texttt{/pattern/g} (counts all) | Match count == replace count |
| \texttt{replace\_all=true}, flags=\texttt{"g"} | \texttt{"g"} (no change) | \texttt{/pattern/g} (replaces all) | \texttt{/pattern/g} (counts all) | Match count == replace count |
| \texttt{replace\_all=true}, flags=\texttt{"i"} | \texttt{"ig"} | \texttt{/pattern/ig} (replaces all) | \texttt{/pattern/ig} (counts all) | Match count == replace count |
| \texttt{replace\_all=false}, flags=\texttt{"g"} | \texttt{"g"} (no change) | \texttt{/pattern/g} (replaces all!) | \texttt{/pattern/g} (counts all) | Both replace all — but user didn't ask for replace\_all! |

The last scenario is most concerning: if the user passes \texttt{regex=true}, \texttt{replace\_all=false}, and \texttt{flags="g"}, the \texttt{g} flag from the user means \texttt{rx} already has \texttt{g}, so \texttt{replace()} replaces ALL occurrences even though \texttt{replace\_all} is \texttt{false}. The error check on line 70-73 (\texttt{if (!replace\_all \&\& replacements > 1)}) should catch this, but it still does the replacement before the check runs — and the replacement is on line 75, which uses \texttt{rx} with \texttt{g} flag, replacing all occurrences regardless.

Wait, let me re-read the order:



\begin{lstlisting}[language=TypeScript]
rx = new RegExp(old_string, rxFlags);                    // 61
const matches = original.match(new RegExp(...));          // 65
replacements = matches ? matches.length : 0;              // 66
if (replacements === 0) { ... }                           // 67
if (!replace_all && replacements > 1) { ... }             // 70
updated = original.replace(rx, new_string);               // 75

\end{lstlisting}



So the check on line 70 would throw an error before the replacement. If \texttt{replace\_all=false} and user passed \texttt{g} in flags, and there are multiple matches, the error on line 70-73 would be thrown. But if there is exactly one match, the replacement on line 75 happens with the \texttt{g} flag, replacing all occurrences — which is inconsistent with \texttt{replace\_all=false}.

This is the deeper issue: the \texttt{g} flag from user flags is not properly separated from the \texttt{replace\_all} semantics.

\subsubsection*{Why It's Technically a Defect}

JavaScript \texttt{RegExp} duplicate flags are silently ignored, so \texttt{"gg"} works the same as \texttt{"g"}. The "double-adding" described in the analysis is technically harmless at runtime but represents:

1. \textbf{Code quality issue}: The same module has two different strategies for ensuring \texttt{g} is present
2. \textbf{Semantic confusion}: User-provided \texttt{g} flag and \texttt{replace\_all=true} have overlapping but not identical semantics
3. \textbf{Maintenance risk}: Future changes to one flag path won't automatically apply to the other


\subsection*{Fix Implementation}
\subsubsection*{Option A: Centralized Flag Construction (Recommended)}



\begin{lstlisting}[language=TypeScript]
// edit.ts — centralized flag logic
if (regex) {
    let rxFlags = flags || "";

    // Separately track: does the user want global matching?
    const userWantsGlobal = rxFlags.includes("g");
    const needsGlobalForReplace = replace_all || userWantsGlobal;

    // Build replacement flags: add 'g' only if needed for replace_all
    let replaceFlags = rxFlags;
    if (replace_all && !userWantsGlobal) {
        replaceFlags += "g";
    }

    // Build match flags: always need 'g' to count all occurrences for validation
    let matchFlags = rxFlags;
    if (!userWantsGlobal) {
        matchFlags += "g";
    }

    let rx: RegExp;
    try {
        rx = new RegExp(old_string, replaceFlags);
    } catch (err: any) {
        throw new Error(`Invalid regex: ${err.message}`);
    }
    const matches = original.match(new RegExp(old_string, matchFlags));
    replacements = matches ? matches.length : 0;
    if (replacements === 0) {
        throw new Error(`Regex pattern not found in ${path}`);
    }
    if (!needsGlobalForReplace && replacements > 1) {
        throw new Error(
            `Regex matched ${replacements} times in ${path}. ` +
            `Pass replace_all=true to replace all, or set flags to include 'g'.`,
        );
    }
    updated = original.replace(rx, new_string);
}

\end{lstlisting}



\textbf{What this fixes:}
1. Centralizes flag building into two clearly named variables
2. Separates match-counting flags from replacement flags
3. Handles the edge case where user provides \texttt{g} without \texttt{replace\_all}

\subsection*{Verification}
The fix is verified through unit tests and integration tests that confirm the corrected behavior:

\begin{lstlisting}[language=TypeScript]
// verification/bug-009-verify.ts
import { describe, it } from "node:test";

// Replicate the fixed logic
function buildFlags(replace_all: boolean, flags?: string): {
    replaceFlags: string;
    matchFlags: string;
    needsGlobal: boolean;
} {
    const rxFlags = flags || "";
    const userWantsGlobal = rxFlags.includes("g");
    const needsGlobalForReplace = replace_all || userWantsGlobal;

    let replaceFlags = rxFlags;
    if (replace_all && !userWantsGlobal) {
        replaceFlags += "g";
    }

    let matchFlags = rxFlags;
    if (!userWantsGlobal) {
        matchFlags += "g";
    }

    return { replaceFlags, matchFlags, needsGlobal: needsGlobalForReplace };
}

function simulateFixedEdit(
    text: string,
    pattern: string,
    replacement: string,
    replace_all: boolean,
    flags?: string,
): { matchCount: number; replaceCount: number } {
    const { replaceFlags, matchFlags } = buildFlags(replace_all, flags);
    const replaceRx = new RegExp(pattern, replaceFlags);
    const matchRx = new RegExp(pattern, matchFlags);

    const allMatches = text.match(matchRx);
    const matchCount = allMatches ? allMatches.length : 0;

    const result = text.replace(replaceRx, replacement);
    const replaceCount = (result.match(new RegExp(replacement, "g")) || []).length;

    return { matchCount, replaceCount };
}

describe("BUG-009: Regex Flag Construction", () => {
    it("should not have duplicate 'g' in flags", () => {
        const { replaceFlags, matchFlags } = buildFlags(true, "g");
        if ((replaceFlags.match(/g/g) || []).length > 1) {
            throw new Error(`Duplicate g in replaceFlags: "${replaceFlags}"`);
        }
        if ((matchFlags.match(/g/g) || []).length > 1) {
            throw new Error(`Duplicate g in matchFlags: "${matchFlags}"`);
        }
    });

    it("should add 'g' to replaceFlags when replace_all=true and no user 'g'", () => {
        const { replaceFlags } = buildFlags(true, "i");
        if (!replaceFlags.includes("g")) {
            throw new Error(`replaceFlags "${replaceFlags}" missing 'g' for replace_all`);
        }
    });

    it("should NOT add 'g' to replaceFlags when replace_all=false even without user 'g'", () => {
        const { replaceFlags } = buildFlags(false, "i");
        if (replaceFlags.includes("g")) {
            throw new Error(`replaceFlags "${replaceFlags}" should NOT have 'g' when replace_all=false`);
        }
    });

    it("should add 'g' to matchFlags even when replace_all=false", () => {
        const { matchFlags } = buildFlags(false, "i");
        if (!matchFlags.includes("g")) {
            throw new Error(`matchFlags "${matchFlags}" missing 'g' for counting`);
        }
    });

    it("should add 'g' to matchFlags when user provides no flags", () => {
        const { matchFlags } = buildFlags(false);
        if (!matchFlags.includes("g")) {
            throw new Error(`matchFlags "${matchFlags}" missing 'g' for counting`);
        }
    });

    it("should not add 'g' to matchFlags when user already provided 'g'", () => {
        const { matchFlags } = buildFlags(false, "g");
        if ((matchFlags.match(/g/g) || []).length > 1) {
            throw new Error(`matchFlags "${matchFlags}" should not duplicate 'g'`);
        }
    });

    it("should have symmetric match and replace counts for all scenarios", () => {
        const text = "a a a";
        const scenarios = [
            { replace_all: true, flags: undefined },
            { replace_all: true, flags: "g" },
            { replace_all: true, flags: "i" },
            { replace_all: false, flags: "g" },
        ];
        for (const s of scenarios) {
            const result = simulateFixedEdit(text, "a", "b", s.replace_all, s.flags);
            if (result.matchCount !== result.replaceCount) {
                throw new Error(
                    `Asymmetry for replace_all=${s.replace_all}, flags=${s.flags}: ` +
                    `match=${result.matchCount}, replace=${result.replaceCount}`,
                );
            }
        }
    });
});

\end{lstlisting}
